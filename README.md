# Web HWP Editor

> 브라우저에서 HWP / HWPX 문서를 열고, 새 문서를 만들고, 직접 편집한 뒤 다시 HWP / HWPX 파일로 저장할 수 있는 웹 기반 한글 문서 편집기입니다.

**현재 버전: v0.5.5**

Web HWP Editor는 별도의 데스크톱 프로그램을 설치하지 않고 웹 브라우저에서 한글 문서를 다루기 위한 프로젝트입니다.  
문서 파일은 현재 구현 기준으로 별도 애플리케이션 서버에 업로드하지 않고 브라우저 안에서 읽고 편집하며, 저장할 때도 브라우저에서 파일을 생성해 다운로드합니다.

> 이 프로젝트는 한글과컴퓨터의 공식 제품이 아닙니다. 복잡한 문서나 업무용 중요 문서는 원본을 보관하고, 저장 후 한컴 한/글 등 실제 사용 환경에서 최종 확인하는 것을 권장합니다.

---

## v0.5.5 안정화 핵심

이번 버전은 기능 추가보다 **문서 라이프사이클과 표 편집의 안전성**을 우선했습니다.

- 오래된 비동기 상태 조회 결과가 새 문서 UI를 덮는 문제 차단
- 파일 읽기/저장 중 편집 영역 잠금과 중복 명령 차단
- 저장 실패 후 편집 잠금 및 저장 버튼 정상 복구
- 편집기 HTML 404를 iframe handshake 전에 감지
- 다운로드 timeout을 HTTP 헤더뿐 아니라 response body 전체 읽기까지 적용
- 빈 문서/잘못된 pageCount 응답 차단
- 줄간격 선택값이 다른 문서의 현재값처럼 남아 보이는 문제 수정
- 선택한 일부 행/열의 크기 맞추기가 선택 밖 셀까지 변경하던 문제 수정
- 큰 병합 셀의 최소 높이를 보존
- 표 geometry 입력값 검증 강화

검증 기록: Chrome 33+6, Edge 33+6 시나리오 통과. 로컬 단위/회귀 검사 11/11 통과.

## 2. 가장 빠르게 사용하기

웹에 배포된 Web HWP Editor를 연 뒤 아래 순서로 사용하면 됩니다.

### 새 문서 만들기

1. **새 문서 시작** 버튼을 누릅니다.
2. 빈 HWP 1페이지가 생성됩니다.
3. 문서 영역을 클릭하고 바로 입력합니다.
4. 필요한 글자/문단/표 서식을 적용합니다.
5. **HWP 저장** 버튼 또는 Ctrl + S를 누릅니다.
6. 새 문서는 기본적으로 **새 문서.hwp** 이름으로 다운로드됩니다.

새 문서는 내부적으로 검증된 빈 HWP 템플릿인 public/blank2010.hwp를 불러와 일반 HWP 문서와 동일한 편집 경로로 처리합니다.

### 기존 HWP / HWPX 열기

다음 방법 중 하나를 사용할 수 있습니다.

- 상단의 **열기** 버튼
- 시작 화면의 **파일 열기**
- HWP/HWPX 파일을 화면에 드래그 앤 드롭
- Ctrl + O

지원 확장자:

- .hwp
- .hwpx

문서를 열면 원본 형식에 맞게 저장 버튼도 HWP 또는 HWPX로 변경됩니다.

### 저장

- 새 HWP 문서: 새 문서.hwp
- 기존 HWP: 원본이름_edited.hwp
- 기존 HWPX: 원본이름_edited.hwpx

저장은 원본 파일을 직접 덮어쓰지 않고 **새 파일 다운로드** 방식으로 동작합니다.  
따라서 원본 파일을 안전하게 보관할 수 있습니다.

## 5. 표 사용법

v0.5.5에서는 표 편집 안정성을 중요하게 다루고 있습니다.

### 표 만들기

1. 문서에서 표를 넣을 위치에 커서를 둡니다.
2. **표 만들기**를 누릅니다.
3. 원하는 줄과 칸을 선택합니다.
4. 만들어진 셀 안에 내용을 입력합니다.

### 줄/칸 추가 또는 삭제

표 안에 커서를 둔 상태에서:

- 줄/칸 추가
- 줄/칸 삭제

기능을 사용할 수 있습니다.

현재 선택 상태에서 사용할 수 없는 명령은 자동으로 비활성화됩니다.

### 표 전체 선택

표 안에 커서를 둔 뒤 **표 전체 선택**을 누르면 현재 표의 모든 셀을 선택할 수 있습니다.

이 기능은 다음 작업에 특히 편리합니다.

- 전체 행 높이 정리
- 전체 열 너비 정리
- 표 전체 셀 편집 전 선택

### 여러 셀 직접 선택

셀 안에서 F5를 두 번 누른 뒤 방향키 등을 이용해 셀 범위를 선택할 수 있습니다.

셀 합치기, 높이 맞추기, 너비 맞추기 같은 기능은 선택 범위가 올바른 경우에만 실행됩니다.

### 셀 합치기

1. 서로 붙어 있는 셀을 직사각형 형태로 선택합니다.
2. **셀 합치기**를 누릅니다.

떨어져 있는 셀이나 올바르지 않은 선택은 병합하지 않고 오류 메시지를 표시하도록 방어 로직이 들어 있습니다.

### 셀 나누기

1. 나눌 셀 또는 지원되는 셀 범위를 선택합니다.
2. **셀 나누기**를 누릅니다.
3. 나누기 옵션을 지정합니다.

셀 분할 뒤 글자 영역과 표 레이아웃이 깨지는 문제를 줄이기 위한 회귀 방어가 포함되어 있습니다.

### 셀 높이 같게

1. 높이를 맞출 연속된 셀/행을 선택합니다.
2. **높이 같게**를 누릅니다.

단순 저장값만 사용하는 대신 실제 렌더링된 셀 높이까지 고려해서 표의 행 높이를 계산합니다.

### 셀 너비 같게

1. 너비를 맞출 연속된 셀/열을 선택합니다.
2. **너비 같게**를 누릅니다.

선택 영역의 전체 너비를 유지하면서 각 열에 정수 HWP 단위로 분배해 누적 반올림 오차를 줄입니다.

### 표 기능에서 현재 제한되는 경우

안전하지 않은 구조 변경은 억지로 실행하지 않고 중단하도록 설계했습니다.

예:

- 떨어진 셀 선택
- 올바르지 않은 비직사각형 선택
- 일부 중첩 표의 셀 병합/나누기
- 중첩 표의 높이/너비 일괄 맞춤

이 경우 화면에 오류 안내가 표시됩니다.

## 6. 문서 보호와 저장 상태

Web HWP Editor는 편집 중 실수로 작업을 잃는 것을 줄이기 위해 다음 상태를 관리합니다.

- 새 문서 여부
- 저장되지 않은 변경사항 여부
- 현재 저장 중인지 여부
- 현재 문서 페이지 수
- 현재 페이지
- 명령 실행 가능 여부

저장하지 않은 변경사항이 있는 상태에서 새 문서를 만들거나 다른 파일을 열면 확인 절차가 동작합니다.

브라우저 창을 닫거나 페이지를 벗어날 때도 저장되지 않은 변경사항이 있으면 브라우저 경고가 표시될 수 있습니다.

저장 작업 중에는 다시 저장하거나 문서를 교체하는 동작을 잠시 막아 중복 실행을 방지합니다.

## 7. 개인정보 / 문서 데이터 처리

현재 Web HWP Editor의 기본 구조에서는 사용자가 연 HWP/HWPX 문서를 별도 애플리케이션 서버로 전송하지 않습니다.

기본 흐름:

1. 브라우저 File API로 로컬 파일 읽기
2. 브라우저 안의 HWP 편집 엔진에서 문서 처리
3. 브라우저 메모리에서 편집
4. HWP/HWPX 데이터를 브라우저에서 생성
5. Blob 다운로드 방식으로 사용자 PC에 저장

즉, 일반적인 사용 흐름은 **브라우저 로컬 처리 중심**입니다.

다만 이 프로젝트를 수정해 별도의 서버 저장, 분석 API, 로그인, 클라우드 기능 등을 추가한다면 해당 구현에 맞는 개인정보 및 보안 정책을 별도로 적용해야 합니다.

# 설치 및 실행

## 9. 저장소 받기

Git이 설치되어 있다면:

~~~bash
git clone https://github.com/kdc916/Web-HWP-Editor.git
cd Web-HWP-Editor
~~~

ZIP으로 다운로드한 경우 압축을 풀고 해당 폴더로 이동하면 됩니다.

---

## 10. 로컬에서 실행

Node.js가 필요합니다. 최신 LTS 버전을 권장합니다.

현재 v0.5.5는 필요한 편집기 자산을 vendor 폴더에 포함하고 있어 일반적인 npm 패키지 설치 없이 바로 로컬 서버를 실행할 수 있습니다.

~~~bash
npm start
~~~

실행 후 터미널에 표시되는 로컬 주소를 Chrome 또는 Edge에서 엽니다.

일반적으로 다음과 같은 형태입니다.

~~~text
http://127.0.0.1:4173/
~~~

### 중요

index.html 파일을 더블 클릭하여 file:// 방식으로 직접 여는 것은 권장하지 않습니다.

ES Module, iframe, WASM 등의 브라우저 보안 정책 때문에 반드시 다음 중 하나로 실행하세요.

- npm start
- GitHub Pages
- 일반 HTTP/HTTPS 정적 웹 서버

# GitHub Pages 배포

## 12. 가장 간단한 배포 방법

이 프로젝트는 GitHub Actions 없이 GitHub Pages의 **Deploy from a branch** 방식으로 바로 배포할 수 있습니다.

### 1) 저장소 Fork 또는 복사

이 저장소를 Fork하거나 자신의 GitHub 저장소로 복사합니다.

### 2) GitHub Pages 설정

GitHub 저장소에서:

**Settings → Pages**

로 이동합니다.

설정:

- Source: Deploy from a branch
- Branch: main
- Folder: /docs

그 뒤 Save를 누릅니다.

### 3) 배포 확인

GitHub Pages 배포가 완료되면 생성된 Pages 주소에서 Web HWP Editor를 바로 사용할 수 있습니다.

v0.5.5는 주요 자산 경로를 상대 경로로 처리하기 때문에 저장소 이름이 달라져도 기존처럼 /Web-HWP-Editor/ 경로를 코드에 일일이 수정할 필요가 없습니다.

### 4) 수정 후 다시 배포

소스를 수정했다면:

~~~bash
npm run build
~~~

을 실행합니다.

그러면 docs 폴더가 다시 생성/갱신됩니다.

변경된 docs 내용을 main 브랜치에 커밋하면 GitHub Pages가 새 버전을 배포합니다.

### 이전 화면이 계속 보일 때

브라우저 캐시 때문에 이전 버전이 남아 보일 수 있습니다.

Windows:

~~~text
Ctrl + Shift + R
~~~

또는:

~~~text
Ctrl + F5
~~~

macOS:

~~~text
Cmd + Shift + R
~~~

을 사용해 강력 새로고침하세요.

### 서버 설정 시 확인할 것

- .wasm 파일 접근 가능
- JavaScript Module 파일 접근 가능
- iframe 내부 Studio 자산 접근 가능
- 폰트 파일 접근 가능
- 가능하면 .wasm을 application/wasm MIME Type으로 제공
- HTTPS 환경 권장

이 프로젝트는 서버 렌더링이나 데이터베이스가 필수인 애플리케이션이 아닙니다.

### index.html / app.html

최상위 `index.html`은 `docs/` 배포본으로 이동하는 안내 페이지이고, 실제 Web HWP Editor 화면 소스는 `app.html`입니다.

새 문서, 열기, 저장, 인쇄, 서식, 표 기능, 상태 표시 UI가 정의되어 있습니다.

### js/app.js

웹 UI와 실제 HWP 편집 엔진을 연결합니다.

담당 기능:

- 편집기 초기화

- 저장/다운로드
- 드래그 앤 드롭
- 단축키

- 페이지 상태
- 명령 활성화 상태
- 인쇄
- Studio 기본 도구 토글

### js/table-geometry.js

표의 높이/너비 균등화에 사용하는 계산 로직입니다.

HWP 내부 단위와 실제 렌더링 높이를 고려하고, 열 너비 분배 시 정수 단위 오차가 누적되지 않도록 처리합니다.

### public/blank2010.hwp

새 문서를 만들 때 사용하는 빈 HWP 템플릿입니다.

### vendor/editor

부모 웹 페이지와 내부 Studio 사이를 연결하는 편집기 SDK입니다.

### vendor/studio

실제 HWP/HWPX를 표시하고 편집하는 브라우저 편집 엔진과 WASM/폰트/정적 자산입니다.

GitHub Pages에 배포되는 완성본입니다.

소스 수정 후 npm run build를 실행하면 배포본을 갱신할 수 있습니다.

# v0.5.5 주요 안정화

## 20. 새 문서 시작 문제

과거 버전에서는 **새 문서 시작**을 눌러도 편집 화면이 나타나지 않는 경우가 있었습니다.

v0.5.5에서는 다음 방식으로 안정화했습니다.

- Studio를 display:none 상태로 초기화하지 않음
- 편집기 영역의 실제 크기를 유지한 상태에서 iframe/canvas 생성
- blank2010.hwp를 일반 문서와 동일한 loadFile 경로로 로드
- 첫 문서 로드의 불필요한 저장 경고 우회
- 편집기 초기화 실패를 명확하게 오류 처리
- 저장/로드 중 중복 명령 차단

---

## 21. 표 안정화

표는 일반 문서 편집에서 자주 사용되는 핵심 기능이기 때문에 v0.5.x에서 집중적으로 보강했습니다.

- 셀 선택 상태 확인

- 떨어진 셀 크기 맞춤 방지
- 중첩 표 위험 작업 차단
- 실제 렌더링 높이 반영
- HWP 정수 단위 너비 분배
- Undo/Redo 가능한 구조 변경
- 표 기능 오류를 사용자에게 Toast로 전달

# 알려진 제한사항

- 모든 글꼴의 100% 동일한 배치
- 중첩 표의 모든 구조 변경
- 모든 인쇄 환경
- 모든 모바일 환경
- 모든 브라우저
- 한컴 한/글과 완전히 동일한 페이지 레이아웃

따라서 중요한 원본 문서는 반드시 별도 보관하세요.

# 문제 해결

## 23. 새 문서를 눌러도 화면이 나오지 않을 때

## 24. HWP/HWPX 파일이 열리지 않을 때

확인할 것:

- 확장자가 .hwp 또는 .hwpx인지
- 파일이 손상되지 않았는지
- 너무 복잡하거나 특수한 문서인지
- 브라우저 Console에 WASM/Studio 오류가 있는지

원본 파일은 별도로 보관한 상태에서 테스트하세요.

---

## 25. 저장 버튼을 눌렀는데 파일이 보이지 않을 때

- 브라우저 다운로드 차단 확인
- 다운로드 폴더 확인
- 여러 파일 자동 다운로드 권한 확인
- 브라우저 팝업/보안 설정 확인

저장 시 브라우저 다운로드 기능을 사용합니다.

---

## 26. GitHub Pages에서 이전 버전이 보일 때

가장 먼저 강력 새로고침을 해보세요.

그래도 이전 버전이라면:

1. docs/DEPLOYED_VERSION.txt 확인
2. docs/index.html이 최신인지 확인
3. main / docs Pages 설정 확인
4. GitHub Pages 배포가 끝났는지 확인
5. 브라우저 캐시 삭제 후 재접속
